# AI 应用开发：模型部署与服务化

## 1. 部署模式对比

| 模式 | 适用场景 | 优缺点 |
|------|----------|--------|
| 托管 API | 快速验证、波动流量 | 零运维，按量付费，可能有延迟和数据合规顾虑 |
| 自建推理（GPU 服务器） | 稳定大吞吐、数据敏感 | 成本可控，需要运维 GPU 集群 |
| 边缘推理 | 低延迟、离线场景 | 设备异构，模型需压缩量化 |
| 混合架构 | 核心服务自建 + 长尾走 API | 平衡成本与可用性 |

## 2. 推理引擎选型

- vLLM：高吞吐、PagedAttention、连续批处理，适合生产。
- TGI（Text Generation Inference）：HuggingFace 官方，生态好。
- llama.cpp / Ollama：CPU/混合推理，适合小规模或边缘。
- TensorRT-LLM：NVIDIA 深度优化，适合极致性能场景。

## 3. vLLM 部署示例

```bash
# 安装
pip install vllm

# 启动 OpenAI 兼容 API
vllm serve Qwen/Qwen2-7B-Instruct \
  --host 0.0.0.0 \
  --port 8000 \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.90 \
  --tensor-parallel-size 2
```

客户端调用：

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="not-needed")
resp = client.chat.completions.create(
    model="Qwen/Qwen2-7B-Instruct",
    messages=[{"role": "user", "content": "解释 TCP 三次握手"}],
    temperature=0.1
)
print(resp.choices[0].message.content)
```

## 4. 模型量化

- GPTQ / AWQ：4bit 权重量化，显存占用降低 ~4x，速度基本不变。
- GGUF（llama.cpp）：适合 CPU 推理，灵活分级量化。
- bitsandbytes：训练/推理混合精度，简单易用。

```python
from transformers import AutoModelForCausalLM, BitsAndBytesConfig

bnb_config = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_use_double_quant=True)
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2-7B-Instruct",
    quantization_config=bnb_config,
    device_map="auto"
)
```

## 6. 网关与流量管理

- 统一入口：Nginx/Envoy 反代多个模型服务。
- 按模型/租户限流、鉴权、日志。
- 请求队列与优先级调度（如 Redis 队列 + 消费者模式）。

```nginx
location /vllm/ {
    proxy_pass http://vllm_backend/v1/;
    limit_req zone=ai_req burst=20 nodelay;
    proxy_read_timeout 120s;
}
```

## 7. 可观测性

- 指标：请求速率、延迟（P50/P95/P99）、tokens/s、GPU 利用率。
- 日志：请求体采样、错误栈、模型版本。
- 链路追踪：OpenTelemetry + Jaeger/Zipkin。

## 8. 成本优化

- 批处理合并同类请求，提高 GPU 利用率。
- 语义缓存：对相似查询直接返回缓存结果。
- 分级路由：简单问题用小模型，复杂问题路由到大模型。
- Spot/抢占式实例适合离线批处理任务。

## 9. 安全

- API Key 鉴权 + IP 白名单。
- 输入输出过滤：PII 脱敏、违规内容拦截。
- 限流防止滥用。
- 私有部署走 VPN/专线，不暴露公网。
