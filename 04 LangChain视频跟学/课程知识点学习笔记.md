## 一、大模型接入与调用

### 1.1 两种接入方式

| 方式 | 代表 | 特点 |
|------|------|------|
| **云端 API** | 阿里云百炼平台 | 满参数模型，有免费额度，无需本地硬件 |
| **本地部署** | Ollama | 开源软件，本地运行，依赖硬件性能 |

### 1.2 阿里云百炼平台接入

**流程：**
```
注册/登录 → 实名认证（支付宝扫码） → 创建 API Key → 安装 openai 库 → 编写代码调用
```

**环境变量保护 API Key：**
```python
# 不推荐：API Key 明文写在代码中
client = OpenAI(api_key="sk-xxx")   # ❌ 安全隐患

# 推荐：通过环境变量读取
# 系统环境变量：OPENAI_API_KEY=sk-xxx  /  DASHSCOPE_API_KEY=sk-xxx
import os
from openai import OpenAI
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
```

- `OPENAI_API_KEY`：用于 openai 库
- `DASHSCOPE_API_KEY`：用于 langchain 库

### 1.3 Ollama 本地部署

**Ollama 简介：** 简化大型语言模型本地部署和运行的开源软件。

**部署步骤：**
1. 官网下载安装客户端（https://ollama.com）
2. 命令行运行模型：`ollama run 模型名称`
3. 模型管理命令：

| 命令 | 作用 |
|------|------|
| `ollama list` | 列出已下载的模型 |
| `ollama pull 模型名` | 下载指定模型 |
| `ollama run 模型名` | 运行模型（不存在自动下载） |

**硬件选型参考：**
| 显存 | 推荐参数量 |
|------|-----------|
| 集显 | 1.5b 左右 |
| 4G 独显 | 8b 以内 |
| 8G 独显 | 14b 以内 |

**代码调用 Ollama 本地模型：** 只需改两处
```python
client = OpenAI(
    base_url="http://localhost:11434/v1",  # 改为本地地址
    # api_key 可以留空
)
# model 改为本地模型名，如 "qwen3:4b"
```

### 1.4 OpenAI 库基础使用

**核心流程：**

```python
from openai import OpenAI

# 1. 创建客户端
client = OpenAI(
    api_key="your_key",
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1"
)

# 2. 调用模型
response = client.chat.completions.create(
    model="qwen3-max",
    messages=[
        {"role": "system", "content": "你是一个Python编程专家。"},
        {"role": "user", "content": "for循环输出1到5的数字"}
    ]
)

# 3. 处理结果
print(response.choices[0].message.content)
```

**三种角色：**

| 角色 | 说明 |
|------|------|
| `system` | 设定助手行为、角色、规则，全局背景设定 |
| `assistant` | AI 助手的回答（可人为预设） |
| `user` | 用户提问 |

**流式输出（stream）：**
```python
response = client.chat.completions.create(
    ...,
    stream=True   # 开启流式输出
)
for chunk in response:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end='', flush=True)
```

**多轮对话：** 将历史消息一并传入 messages 列表
```python
messages = [
    {"role": "system", "content": "你是AI助理"},
    {"role": "user", "content": "小明有2条宠物狗"},
    {"role": "assistant", "content": "好的"},
    {"role": "user", "content": "总共有几个宠物？"}
]
```

> ⚠️ 历史消息是一次性的，生产系统需持久化到文件/数据库。

## 二、LLM 基础理论

### 2.1 什么是 LLM

**大语言模型（Large Language Model）**：一种人工智能模型，旨在理解和生成人类语言，可处理文本分类、问答、翻译、对话等多种自然语言任务。

### 2.2 语言模型技术发展四阶段

```
1. 基于规则和统计的语言模型
2. 神经语言模型
3. 预训练语言模型
4. 大语言模型
```

### 2.3 LLM 三大类别架构

所有 LLM 基于 **Transformer** 架构（2017, "Attention Is All You Need"）。

| 类别 | 代表 | 结构 | 原理 | 适用场景 |
|------|------|------|------|----------|
| **自编码模型 (AE)** | BERT | Encoder-Only | 随机 MASK 单词，根据上下文预测 | 自然语言理解（分类、情感分析、提取式问答） |
| **自回归模型 (AR)** | GPT | Decoder-Only | 从左往右学习，上一步结果预测下一步 | 自然语言生成（摘要、翻译、长文本生成） |
| **序列到序列** | T5 | Encoder-Decoder | 编码+解码，序列到序列转换 | 需要内容理解和生成的任务（机器翻译） |

## 四、提示词工程

### 4.1 核心概念

**提示工程（Prompt Engineering）**：在不更新模型权重的情况下，通过设计输入指令来引导模型行为以获得所需结果的方法。

**本质：** 大模型 = `用户输入 → 模型输出`。提示词优化是所有大模型应用开发的基础必修课。

### 4.2 提示词六大技巧

| 技巧 | 说明 | 示例 |
|------|------|------|
| ① **详细描述** | 清晰表达需求，越具体越好 | ❌ "写封情书" → ✅ "用温柔的话语写情书，表达仰慕和思念，不低于500字" |
| ② **角色扮演** | 让模型充当特定角色 | "你是一个 AI 算法面试官，对我进行面试" |
| ③ **分隔符** | 用符号标出输入的不同部分 | `"""在此插入文本"""`、XML 标签、中括号 |
| ④ **指定步骤** | 复杂任务拆分为明确的步骤 | "步骤1：总结文本 → 步骤2：翻译成英语" |
| ⑤ **提供例子** | Few-shot，先给示例 | 先展示正确输出格式，再让模型按格式回答 |
| ⑥ **参考文本** | 提供参考资料降低幻觉 | "根据以下文章回答问题，找不到答案就说不知道" |

**核心原则：** 任何 Prompt 技巧，都不如 **清晰的表达需求**。

### 4.3 Zero-shot vs Few-shot

| 概念 | 模型训练层面 | 提示词优化层面 |
|------|-------------|---------------|
| **Zero-shot** | 训练时未见该类别的样本，利用属性关联迁移识别 | 不提供示例，仅用语言描述任务，依赖模型预训练知识 |
| **Few-shot** | 基于少量样本快速泛化识别新类别 | 给模型少量示例，引导对齐示例输出格式 |

### 4.4 实战案例：金融文本分类

**目标：** 将金融文本分为「新闻报道、公司公告、财务报告、分析师报告」四类。

**Prompt 设计思路：**
1. Few-shot 方式给予分类示例
2. 要求模型按指定格式输出

```python
examples_data = {
    '新闻报道': '今日，股市经历了一轮震荡...',
    '财务报告': '本公司年度财务报告显示...',
    '公司公告': '本公司高兴地宣布成功完成...',
    '分析师报告': '最新的行业分析报告指出...'
}

def init_prompt(examples):
    prompt_list = [{"role": "system", "content": "你是一个金融专家..."}]
    for class_type, example_text in examples.items():
        prompt_list.append({"role": "user", "content": example_text})
        prompt_list.append({"role": "assistant", "content": class_type})
    return prompt_list

messages = init_prompt(examples_data)
response = client.chat.completions.create(
    model="qwen3-max",
    messages=messages + [{"role": "user", "content": f"请分析如下句子是什么类别：{question}"}]
)
```

### 4.5 实战案例：金融文本信息抽取

**目标：** 从股票描述中抽取 SPO 三元组（日期、股票名称、开盘价、收盘价、成交量）。

**Schema 定义：**
```python
schema = {
    '金融': ['日期', '股票名称', '开盘价', '收盘价', '成交量']
}
```

**关键技巧：** 要求模型以 JSON 格式输出，未提及信息用 `['原文中未提及']` 表示。

### 4.6 实战案例：金融文本匹配

**目标：** 判断两段金融文本是否描述同一事件（语义匹配）。

**策略：** 先用 Zero-shot 让模型直接判断，如效果不佳再补充 Few-shot 示例。

## 五、JSON 数据格式

### 5.1 JSON 基础

JSON（JavaScript Object Notation）：轻量级数据交换格式。

| 格式 | 对比 |
|------|------|
| 纯文本 | 非结构化，抽取信息不方便 |
| CSV | 结构化，但无 Schema |
| **JSON** | 结构化，每条数据带 Schema，空间占用大 |

### 5.2 JSON 两种结构

```python
# JSON 对象 → Python 字典
{
    "age": 11,
    "name": "周杰轮",
    "hobby": ["唱", "跳", "rap"],
    "other": {"身高": 172, "体重": 68}
}

# JSON 数组 → Python 列表（内含字典）
[
    {"name": "周杰轮", "age": 11},
    {"name": "蔡依临", "age": 12}
]
```

### 5.3 Python JSON 操作

```python
import json

# 字典/列表 → JSON 字符串
json_str = json.dumps(data, ensure_ascii=False)

# JSON 字符串 → 字典/列表
data = json.loads(json_str)
```

## 六、RAG 基础概念

### 6.1 RAG 定义与作用

RAG（Retrieval Augmented Generation，检索增强生成）：检索相关资料后再回答。

**解决的问题：**
- 向知识库添加**未来知识**（模型训练之后的信息）
- 添加**私有知识**（企业内部文档）
- 提供参考资料，**规避模型幻觉**

### 6.2 RAG 两条主线

```
离线流程（知识库构建）：
  本地知识文件 → 加载和读取 → 文本切分 → 向量数据库

在线流程（问答）：
  用户 Query → Query 向量化 → 向量匹配检索
  → Prompt 工程（组装上下文） → 提交 LLM 生成答案
```

### 6.3 RAG vs Tool Calling

| | RAG | Tool Calling |
|--|-----|-------------|
| 查询对象 | 静态知识库 | 动态实时信息 |
| 典型场景 | 文档问答、知识查询 | 查状态、查数据、执行命令 |
| 数据源 | 预先整理的文档 | 外部 API/数据库 |

## 七、LangChain 核心组件

### 7.1 LangChain 简介

LangChain 是一个围绕大语言模型构建应用的框架，核心思想是**组件化 + 链式调用**。

### 7.2 模型支持

LangChain 通过 `langchain_community` 包提供三类模型：

| 模型类型 | 说明 | 示例 |
|----------|------|------|
| **LLMs** | 大语言模型，文本生成 | `Tongyi()` |
| **Chat Model** | 聊天模型，多轮对话 | `ChatTongyi()` |
| **Embeddings Model** | 文本嵌入模型，生成向量 | `DashScopeEmbeddings()` |

三种消息角色（与 OpenAI SDK 对应）：
| LangChain | OpenAI SDK |
|-----------|------------|
| `HumanMessage` | user |
| `AIMessage` | assistant |
| `SystemMessage` | system |

### 7.3 PromptTemplate（通用提示词模板）

```python
from langchain_core.prompts import PromptTemplate

# 定义模板
prompt_template = PromptTemplate.from_template(
    "我的邻居姓{lastname}, 刚生了{gender}, 帮忙起名字。"
)

# 方式一：format 注入
prompt_text = prompt_template.format(lastname="张", gender="女儿")

# 方式二：chain 链式调用（推荐）
chain = prompt_template | model
result = chain.invoke({"lastname": "张", "gender": "女儿"})
```

### 7.4 FewShotPromptTemplate（少样本提示词模板）

```python
from langchain_core.prompts import FewShotPromptTemplate, PromptTemplate

example_template = PromptTemplate.from_template("单词:{word}, 反义词:{antonym}")

example_data = [
    {"word": "大", "antonym": "小"},
    {"word": "上", "antonym": "下"}
]

few_shot_prompt = FewShotPromptTemplate(
    example_prompt=example_template,
    examples=example_data,
    prefix="给出给定词的反义词，有如下示例：",
    suffix="基于示例告诉我：{input_word}的反义词是？",
    input_variables=['input_word']
)

# 注入变量获取最终提示词
prompt_text = few_shot_prompt.invoke({"input_word": "左"}).to_string()
```

**五个核心参数：**
| 参数 | 说明 |
|------|------|
| `example_prompt` | 示例数据的提示词模板 |
| `examples` | 示例数据（list of dict） |
| `prefix` | 示例数据前的内容 |
| `suffix` | 示例数据后的内容 |
| `input_variables` | 注入的变量列表 |

### 7.5 ChatPromptTemplate（聊天模板）

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

chat_template = ChatPromptTemplate.from_messages([
    ("system", "你是一个边塞诗人"),
    MessagesPlaceholder("history"),      # 历史消息占位符
    ("human", "请再来一首唐诗"),
])

history_data = [
    ("human", "你来写一个唐诗"),
    ("ai", "床前明月光..."),
    ("human", "好诗再来一个"),
    ("ai", "锄禾日当午..."),
]

prompt_value = chat_template.invoke({"history": history_data})
```

### 7.6 Chain 链式调用

**核心原理：**「上一个组件的输出作为下一个组件的输入」

```python
# 基本链
chain = prompt_template | model

# 多组件链
chain = prompt_template | model | parser | prompt_template2 | model
```

**前提：** 入链组件需是 `Runnable` 接口的子类。

**`|` 运算符重载：**
```python
# Python 中 a | b 本质调用 a.__or__(b)
# LangChain 的 Runnable 基类重写了 __or__ 方法
# 使得 prompt | model 得到 RunnableSequence 对象
```

### 7.7 StrOutputParser（字符串输出解析器）

**作用：** 将模型输出的 `AIMessage` 类型转为普通字符串。

```python
from langchain_core.output_parsers import StrOutputParser

parser = StrOutputParser()
chain = prompt | model | parser | model  # 可再次传给模型
```

**为什么需要它？** 模型的 `invoke` 方法不接受 `AIMessage` 类型作为输入，但接受字符串。`StrOutputParser` 解决了类型不匹配的问题。

### 7.8 JsonOutputParser（JSON 输出解析器）

**作用：** 将模型输出的 `AIMessage` 转为 Python 字典。

```python
from langchain_core.output_parsers import JsonOutputParser

json_parser = JsonOutputParser()
chain = first_prompt | model | json_parser | second_prompt | model | str_parser
```

**执行流程：**
```
first_prompt → model → json_parser → second_prompt → model → str_parser
 (PromptValue)  (AIMessage)   (dict)       (PromptValue)  (AIMessage)  (str)
```

### 7.9 RunnableLambda（自定义函数入链）

**作用：** 将普通函数包装为 Runnable 接口，加入链中。

```python
from langchain_core.runnables import RunnableLambda

# 方式一：封装为 RunnableLambda
my_func = RunnableLambda(lambda ai_msg: {"name": ai_msg.content})
chain = prompt | model | my_func | prompt2 | model

# 方式二：直接入链（自动转换为 RunnableLambda）
chain = prompt | model | (lambda ai_msg: {"name": ai_msg.content}) | prompt2 | model
```

> `__or__` 的实现支持 `Callable` 接口实例直接入链。

### 7.10 Memory 记忆模块

#### 临时记忆（InMemoryChatMessageHistory）

```python
from langchain_core.runnables.history import RunnableWithMessageHistory
from langchain_core.chat_history import InMemoryChatMessageHistory

# 存储会话的字典
chat_history_store = {}

def get_history(session_id: str):
    if session_id not in chat_history_store:
        chat_history_store[session_id] = InMemoryChatMessageHistory()
    return chat_history_store[session_id]

# 创建带历史记忆的链
conversation_chain = RunnableWithMessageHistory(
    base_chain,
    get_history,
    input_messages_key="input",
    history_messages_key="chat_history"
)

# 使用
session_config = {"configurable": {"session_id": "user_001"}}
conversation_chain.invoke({"input": "小明有一只猫"}, session_config)
conversation_chain.invoke({"input": "共有几只宠物？"}, session_config)
```

#### 长期记忆（FileChatMessageHistory）

**原理：** 继承 `BaseChatMessageHistory`，实现三个方法：

| 方法 | 说明 |
|------|------|
| `add_messages` | 添加消息到历史 |
| `messages` | 获取历史消息 |
| `clear` | 清除历史 |

以 session_id 为文件名，不同会话不同文件，存储为 JSON 格式。程序重启后仍可读取历史。

### 7.11 RunnablePassthrough

**作用：** 让向量检索也能加入链式调用，作为数据传递的通道组件。

**jq 语法示例：**

**JSONLines 格式：** 每行一个独立的 JSON 对象（字典）。

```python
from langchain_community.document_loaders import TextLoader

loader = TextLoader("file.txt", encoding="utf-8")
docs = loader.load()  # 整个文件作为一个 Document
```

### 8.7 RecursiveCharacterTextSplitter（文本分割器）

LangChain 官方推荐的默认分割器，按自然段落分割大文档：

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,           # 每段最大字符数
    chunk_overlap=50,         # 段间重叠字符数
    separators=["\n\n", "\n", "。", "！", "？", ".", "!", "?", " ", ""],
    length_function=len,      # 字符统计函数
)

split_docs = splitter.split_documents(docs)
```

**参数作用：**
- `chunk_size`：控制每段大小，影响检索精度
- `chunk_overlap`：保持段间上下文连续性
- `separators`：分割优先级，段落 > 句子 > 词 > 字符

## 九、向量存储与检索

### 9.1 LangChain 向量存储 API

所有向量存储统一提供三个接口：

```python
# 添加文档
vector_store.add_documents(documents=[doc1, doc2], ids=["id1", "id2"])

# 删除文档
vector_store.delete(ids=["id1"])

# 相似度搜索
similar_docs = vector_store.similarity_search("your query", k=4)
```

### 9.2 两种向量存储

```python
# 1. 内存向量存储（临时）
from langchain_core.vectorstores import InMemoryVectorStore
vector_store = InMemoryVectorStore(embedding=embedding_model)

# 2. Chroma 外部数据库（持久化）
from langchain_chroma import Chroma
vector_store = Chroma(
    collection_name="example_collection",
    embedding_function=embedding_model,
    persist_directory="./chroma_langchain_db",
)
```

### 9.3 完整 RAG 检索流程

```
1. 文本 → Embedding 模型 → 向量
2. 向量存入向量存储（InMemoryVectorStore / Chroma）
3. 用户 Query → Embedding 模型 → 查询向量
4. 向量存储相似度搜索 → 返回 top-k 相关文档
5. 文档 + 用户问题 → 组装 Prompt → 调用 LLM → 生成回答
```

## 十、RAG 项目实战

### 10.1 项目需求

以商品衣服为例，构建本地知识库，支持自由更新知识，回答基于本地知识。

**项目结构：**

| 文件 | 作用 |
|------|------|
| `app_file_upload.py` | 知识库更新界面（Streamlit） |
| `app_qa.py` | 对话问答主界面（Streamlit） |
| `config_data.py` | 配置文件 |
| `file_history_store.py` | 长期会话记忆存储 |
| `knowledge_base.py` | 知识库更新服务 |
| `rag.py` | RAG 核心服务 |
| `vector_stores.py` | 向量存储服务 |

### 10.2 离线流程

```
app_file_upload.py → 上传文件
      ↓
knowledge_base.py → 加载和读取文档
      ↓
文本切分（RecursiveCharacterTextSplitter）
      ↓
向量化 → 存入 ChromaDB
```

### 10.3 在线流程

```
用户提问 → Query 向量化 → 向量匹配检索
     ↓
检索到的文档 + 用户问题 → Prompt 工程组装
     ↓
调用 LLM → 生成基于本地知识的回答
```

### 10.4 项目关键设计

- **知识库可更新**：用户可通过 Streamlit 界面上传文件，离线流程被触发
- **长期会话记忆**：`file_history_store.py` 独立实现文件级持久化
- **模块分离**：知识库管理、RAG 服务、向量存储各自独立
